## 二、结论

1. **EEPROM 类型识别成立且无缓存**：空座 → `noresp`；2.5G 猫棒 → `enc=0x20 br=0x20`；10G 模块 → `enc=0x67 br=0x67`。拔掉后立刻失效，插上后立刻可读，说明是真实 I2C 读，不是残留值。
2. **单次 noresp 不可作为判据**：t=0 首次调用 noresp，t=10 又 ok 0x20。实现时必须重试 2~3 次（间隔 1s）再判定空座。
3. **在位检测不依赖 link**：t=60~100 五次都读到 0x20，而 carrier 一直是 0。模块 EEPROM 可访问 ≠ link 建立。
4. **两种模块的 link 延迟差一个数量级**：
   - 10G 模块：插入后 <6s link 10000（与历史"10G 热插拔 4-7s"一致）
   - 2.5G 猫棒：插入后约 50~60s 才 link 2500（本次首次精确测到）
5. **猫棒 50~60s 的建立时间与冷启动 58s 完全吻合**。这说明冷启动能成不是因为"上电那一刻恰好协商成功"，而是驱动 link 轮询一路等着，等到模块自己 ready 时接住；warm reset 失败则是模块没掉电、内部状态未重置，PHY 侧重协商拿不到对端。
6. **插拔不触发 SFP 重新初始化**：整段只有 PHY Link up，没有 sfp_phy_init。SFP 初始化是一次性的（启动 9.5s），之后完全靠 PHY 侧 sgmii 自协商 + link 轮询。

## 三、对方案的影响

- "开机检测占位 + 读类型选协议"这条路：**完全可行**，判据是 `RateEncode`，且无需改驱动即可观测。实现要点是重试去抖。
- 之前 B1 数据推翻了"热插拔都是秒级恢复"的说法，改为"10G 秒级，猫棒 50~60s，且波动可能更大"。
- warm reset 不 link 的修复仍未解决：软件侧无可用的模块复位手段（TX_DISABLE 无效、SSDK port reset/poweroff 不支持）。若采用"开机读类型 → 直接按类型配 PCS"策略，需要重新验证它能否让 warm reset 也 link（因为它跳过了 30s PCS 探测回落，走的是确定性配置）。
